## 二、演示前：环境启动（不在 13 分钟内，提前 10 分钟做完）

### 2.1 启动数据库

**方式 A：本机 MySQL（推荐，演示环境已实测）**

确认 MySQL 服务已启动，`backend/.env` 中以下变量正确：

```ini
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=oes_app
DB_PASSWORD=oes_app_pwd
DB_ROOT_USER=root
DB_ROOT_PASSWORD=root_pwd
```

**方式 B：Docker（Docker Desktop 正常时可用）**

```bash
cd backend
docker compose up -d mysql
```

> 本项目实测环境为 Windows 11 + 本机 MySQL 9.1.0；建表脚本只使用 MySQL 8.0 已有特性（JSON、生成列、CHECK、窗口函数），8.0.16+ 均可执行。

### 2.2 初始化库表（仅演示前执行一次）

```bash
cd backend
copy .env.example .env      # 首次部署；已有 .env 则跳过
npm install
npm run db:init
```

预期输出：`tables=31 (expected 31)`，并列出 3 个种子账号。**这一步会 DROP 同名表，答辩现场禁止执行。**

### 2.3 启动后端

```bash
cd backend
npm run dev
```

预期：控制台输出监听 `3000` 端口、数据库连接成功。验证：

```bash
curl http://localhost:3000/api/v1/health
```

预期：`{"status":"up","database":"connected","version":"1.0.0",...}`

### 2.4 启动前端

```bash
cd frontend
copy .env.example .env      # 首次部署；默认 http://localhost:3000/api/v1
npm install
npm run dev
```

预期：Vite 输出 `http://localhost:5173`。

### 2.5 提前打开 4 个浏览器标签

| 标签 | 地址 | 用途 |
| :---: | --- | --- |
| 1 | `http://localhost:3000/api/v1/health` | 开场证明服务与数据库连通 |
| 2 | `http://localhost:5173/login` | 管理员 / 教师共用登录入口 |
| 3 | `http://localhost:5173/login` | 学生登录入口 |
| 4 | 空白页 | 备用：录屏或截图 |

> 不要提前登录学生账号，避免占用唯一进行中答卷；管理员与教师可提前登录，但演示时重新走一次登录更能说明角色跳转。

## 三、逐段脚本

### T1 · 00:00-01:00 · 环境启动与健康检查（60 秒）

**目标**：用一条真实响应证明"前端—后端—数据库"三件套都在运行，建立可信度。

**操作路径与点击顺序**

1. 切到标签 1：`http://localhost:3000/api/v1/health`。
2. 鼠标指向 `"status":"up"` 与 `"database":"connected"`。
3. 切到标签 2：`http://localhost:5173/login`，展示深色赛博朋克登录页，不登录。

**预期界面表现**

- 健康检查返回 JSON：`status=up`、`database=connected`、`version=1.0.0`。
- 登录页为深色霓虹外壳（`#070a12` 底 + 青→紫→品红渐变），左侧品牌区、右侧登录表单。
- 页面无红色错误提示，浏览器控制台无 500。

**旁白（可直接照读）**

> 各位老师好。演示之前我先用一条健康检查确认环境：服务状态 up，数据库 connected，版本 1.0.0。前端是 React 18 单页应用，后端是 Express 4，数据库是 MySQL，三样都跑在本机，没有依赖任何外部服务。
>
> 登录页是系统的"赛博朋克外壳"，但进入题库、答题、阅卷这些长时间操作的页面后，会切换成浅色高对比的"简洁内核"。这不是为了好看，而是因为答题和阅卷需要低视觉干扰，霓虹只保留在登录和工作台。
>
> 接下来我按真实角色走一遍：管理员建知识点，教师组卷发布，学生答题交卷，教师复核，最后看统计和审计。

**可能失败与兜底话术**

- 健康检查 500 / `database: disconnected`：先看 MySQL 服务是否启动、`backend/.env` 密码是否正确。**不要在现场改密码**，直接说："演示库连接异常，我切换到同一版本的真实执行录屏，路径完全一致。"切标签 4 播放录屏。
- 前端 5173 打不开：确认 `npm run dev` 未退出、端口未被占用。若 30 秒内无法恢复，改用 `frontend/dist/` 静态预览或录屏。
- 登录页样式错乱：浏览器缩放不是 100%，按 `Ctrl+0` 复位；仍异常则换 Edge。

**目标**：展示治理角色的入口、两级知识点模型，以及"题目与统计都挂在知识点树上"的设计。

**操作路径与点击顺序**

1. 标签 2 登录：用户名 `admin`，密码 `Admin@2026`，点击"登录"。
2. 自动进入 `/admin/dashboard`，左侧导航点击"知识点维护"。
3. 进入 `/admin/knowledge-points`，指出已有两级树：计算机基础 → 数据结构 / 计算机网络 / 数据库原理 / Web 安全与鉴权。
4. 点击右上角"+ 新增一级知识点"。
5. 名称填"软件工程"，编码可留空或填 `KP-SE`，排序 `50`，保存。
6. 在"软件工程"行点击"添加子节点"，名称填"需求工程"，保存。

**预期界面表现**

- 保存后 toast 提示"知识点已创建"。
- 树形列表立即出现"软件工程 → 需求工程"，层级、编码、题目数可见。
- 不刷新页面也能看到新节点（前端重新拉取列表）。

**旁白（可直接照读）**

> 管理员不直接参与教学，职责是治理：账号、角色、参数、全局题库监管、审计，以及成绩争议仲裁。
>
> 知识点是两级分类。它不是一个装饰性的字典，题目创建时要挂知识点，统计页的"知识点失分"也按这棵树聚合。所以管理员在这里把分类建好，教师后面建题就能直接选。
>
> 我新增一个一级"软件工程"和一个二级"需求工程"。注意编码可以自动生成，排序决定展示顺序；归档走的是状态变更，不是物理删除，因为历史题目还引用它。

**可能失败与兜底话术**

- 保存 403：确认登录的是 `admin` 而不是教师；管理员权限直通，但 token 过期会 401，重新登录即可。
- 页面空白：刷新一次；若提示 401，说明访问令牌 2 小时过期，重新登录不影响演示。

### T3 · 02:20-04:10 · 教师建题、组卷、锁定（110 秒）

**目标**：展示五种题型、分值校验、手动组卷，以及"试卷被引用前先锁定"的规则。

**操作路径与点击顺序**

1. 标签 2 退出管理员（右上角头像/退出），回到 `/login`。
2. 登录教师：`T2024001` / `Teacher@2026`，进入 `/teacher/dashboard`。
3. 左侧点击"题库与题目"，进入 `/teacher/questions`，指出列表包含单选、多选、判断、填空、简答五种题型，以及"批量导入 / 导出 / 版本历史"入口。
4. 点击"+ 新建题目"进入 `/teacher/questions/new`：
   - 题型选"单选"，题干填"下列哪一项是 HTTP 的无状态解决方案？"
   - 选项 A  Cookie、B  Session、C  JWT、D  缓存，正确答案选 C，分值 5，知识点选"Web 安全与鉴权"。
   - 点击"保存题目"，返回题库列表，指出新题已出现且版本号为 1。
5. 左侧点击"试卷管理"，进入 `/teacher/papers`，点击"+ 新建试卷"。
6. 进入 `/teacher/papers/new`：
   - 试卷名称填"演示卷 · 软件工程综合"。
   - 总分填 `35`，时长 `30` 分钟。
   - 在"手动组卷"标签下，从题库选择 3 道题：**刚新建的单选题（5 分，答案 C）**、种子多选题（10 分，答案 A/B/D）、种子简答题（20 分）。
   - 页面实时显示"题数 3 / 总分 35"，与设定总分一致。
   - 点击"保存试卷"。
7. 返回 `/teacher/papers`，在新试卷行点击"锁定"，确认提示"试卷已锁定，禁止改题目与分值"。

**预期界面表现**

- 题库列表显示五种题型标签、难度、分值、版本号。
- 新建题目保存后 toast"题目已创建"，列表出现新题。
- 组卷页右侧/底部实时累计题数与总分；分值不一致时保存会提示差额。
- 保存后 toast"试卷已创建"，状态为草稿；点击锁定后状态变为"已锁定"，编辑与删除按钮禁用。
- 锁定后再次点击编辑，应提示"已锁定，禁止修改题目与分值"。

**旁白（可直接照读）**

> 教师是系统的主要使用者。题库支持五种题型，答案统一用 JSON 数组存：单选是单元素数组，多选是多元素，判断是布尔，填空按空顺序，简答不存标准答案，存的是采分点。
>
> 我先新建一道单选题，挂到"Web 安全与鉴权"知识点。保存时服务端会校验：单选答案必须恰好一个、选项不能重复、分值必须大于零。校验不过会返回具体的业务码，不是一句"参数错误"。
>
> 接下来组卷。组卷有两条路：手动逐题加入，或者按题型、难度比例、知识点范围随机抽题。随机组卷如果某维度题目不够，会返回缺口明细，**不会**生成一份残缺的试卷——这是需求里明确写的"不足即不生成"。
>
> 我这里手动加 3 题，5 加 10 加 20 等于 35，和设定的总分一致才能保存。保存后是草稿，我手动锁定。为什么先锁定？因为考试一旦引用试卷，题目和分值就不能再变，否则同一场考试不同学生看到的内容会不一致。锁定是三层快照的第一道闸门。

**可能失败与兜底话术**

- 题库为空：说明演示库未初始化，改用种子题库（已有 5 题），跳过新建题目，直接组卷。
- 保存提示总分不一致：现场把总分改成 35，或删掉一题使合计相等；顺势说"这就是服务端的 30101 分值校验，演示环境正好复现"。
- 锁定按钮不可用：试卷已被考试引用会自动锁定，直接进入下一步。
- 题目下拉为空：确认题库归属 `T2024001`；种子题库 owner_id=2 即该教师。

### T4 · 04:10-05:20 · 教师创建并发布考试（70 秒）

**目标**：展示时间窗、任务生成、发布通知，以及"发布后试卷自动锁定"。

**操作路径与点击顺序**

1. 在 `/teacher/papers` 新试卷行点击"创建考试"，跳转 `/teacher/exams/new?paperId=<id>`。
2. 表单填写：
   - 考试名称："演示考试 · 软件工程综合"。
   - 关联试卷：已自动带入刚锁定的试卷（题数 3、总分 35）。
   - 开始时间：当前时间减 10 分钟；结束时间：当前时间加 2 小时。
   - 时长：30 分钟（必须小于窗口长度 130 分钟）。
   - 及格线：20 分；最大作答次数：1；参考班级：班级 1。
   - 打乱题目顺序：开；超时自动交卷：开；防作弊：开，阈值 3。
3. 点击"创建并发布"。
4. 弹出确认后，观察 toast 与考试列表状态。

**预期界面表现**

- 若开始时间早于当前，允许保存并立即进入"已发布"。
- toast："发布成功：生成 N 条考试任务，通知 N 人"（N 为班级 1 的学生数，种子环境为 1）。
- `/teacher/exams` 列表出现新考试，状态"已发布"，操作栏有"监控 / 考生任务 / 补考授权 / 取消"。
- 返回 `/teacher/papers`，该试卷状态为"已锁定"。

**旁白（可直接照读）**

> 发布考试时服务端做三件事：第一，校验时间窗和试卷状态，时长不能超过窗口；第二，按参考范围生成考试任务，一个学生一条；第三，发站内通知。
>
> 这里我把开始时间设在 10 分钟前、结束设在 2 小时后，学生现在就能进。时长 30 分钟，小于窗口的 130 分钟，所以截止时间取"开考时间加 30 分钟"和"窗口结束"两者中较早的一个。
>
> 发布成功后，试卷自动锁定。后面如果我要改题目，只能先取消考试；这就是"引用即锁定"的约束，用状态而不是口头约定来保证。

**可能失败与兜底话术**

- 提示"开始时间不能早于当前"：把开始时间改为当前加 1 分钟，告诉评委"等 60 秒开考"，先继续讲 T5 的机制，时间到了再操作。
- 提示"试卷未锁定"：回 T3 点锁定；或改用种子已锁定试卷（5 题 / 50 分 / 含 1 道简答）。
- 任务数为 0：班级 1 没有学生，改用"按学生指定"选择 `S2024001`，或先跑 `npm run seed:demo` 补充学生。
- 发布 409：考试窗口与已有考试冲突的概率很低；换一个名称与时间再试。

### T5 · 05:20-08:40 · 学生答题、暂存、断线恢复、交卷（200 秒，重点）

**目标**：完整展示服务端计时、3 秒暂存、切题立即保存、刷新恢复、答题卡、交卷幂等。这是全场最需要讲清楚的一段。

**操作路径与点击顺序**

1. 切到标签 3：`http://localhost:5173/login`，登录 `S2024001` / `Student@2026`。
2. 进入 `/student/dashboard`，点击"查看我的考试"或左侧"考试列表"，进入 `/student/exams`。
3. 找到"演示考试 · 软件工程综合"，点击"进入考试"。
4. 弹出考前须知（考试窗口、时长、次数、暂存与断线说明），点击"我已阅读考前须知，确认开始作答"。
5. 进入全屏答题页 `/student/attempts/<attemptId>`：
   - 指顶部倒计时："剩余 29:xx"，说明来自服务端。
   - 第 1 题单选：选择 C（JWT），观察右上/底部保存状态从"待保存…"变为"保存中…"再到"已保存 HH:mm:ss"。
   - 第 2 题多选：**跳过不答**，口头说明少选得半分 / 错选不得分的策略，不实际勾选，留作"未答"演示。
   - 第 3 题简答：输入三行要点：Header、Payload、Signature；Header 描述算法；Signature 防篡改（Payload 的声明与过期时间故意不写，留给教师扣分）。
   - 打开答题卡，指出第 1、3 题已答、第 2 题未答。
6. 刷新页面（`Ctrl+R`）：重新进入同一答卷路由，展示剩余时间与已保存答案恢复，且倒计时没有"重新从 30 分钟开始"。
7. 点击"检查并交卷"，弹窗显示"剩余 1 题未作答"，点击"确认交卷"。
8. 展示交卷结果弹窗：交卷方式、客观分、待阅主观题数、是否重放。

**预期界面表现**

- 答题页为独立全屏布局，顶部固定倒计时条，左侧题目区，右侧答题卡。
- 保存状态文案依次为"待保存… / 保存中… / 已保存 HH:mm:ss / 保存失败，重试中"。
- 切换题目时立即触发一次保存（不等 3 秒）。
- 刷新后 URL 不变、答案回填、剩余秒数连续（误差在 30 秒校准周期内）。
- 答题卡用颜色区分已答/未答/当前题；未答题在交卷确认弹窗中列出题号。
- 交卷结果：客观分立即出现（按推荐操作：单选 5 分、第 2 题未答 0 分，客观分 5），待阅主观题 1 道，交卷方式"手动交卷"。
- 交卷后再次点击交卷或刷新，页面显示"该答卷已交卷"，不会重复判分。

**旁白（可直接照读）**

> 这一段是系统的核心，请老师重点看三件事：倒计时、暂存、交卷。
>
> 第一，倒计时。页面上的秒数不是本地自己减出来的。开考时服务端一次性写入截止时间，之后不再变；恢复接口返回服务端时间、截止时间和剩余秒数，前端算一个"服务端时间减本地时间"的偏移量，本地每秒按"截止时间减（本地时间加偏移）"渲染，每 30 秒再校准一次。所以把系统时间改快或改慢，只影响显示，不影响判定；交卷时服务端还会再判一次，超期就按超时处理。
>
> 第二，暂存。我改答案后不会每敲一个字就发请求，而是 3 秒防抖；切题会立即保存。右上角能看到"保存中"到"已保存"的变化。如果保存失败，答案会留在待保存队列里重试，不会阻断答题。暂存只更新答案，**不修改截止时间**——否则学生频繁暂存就能"续时"。
>
> 第三，断线恢复。我现在刷新页面。可以看到剩余时间没有重置，之前答的内容也回来了。因为恢复接口会按考试和考生找进行中的答卷，有就直接返回并标记重放，不会新建一份、也不会重复计时。
>
> 现在交卷。我故意留了一道多选没答，确认弹窗会告诉我剩几题。交卷前页面会先等待进行中的暂存结束，再强制提交一次，保证已答内容不丢。
>
> 服务端收到交卷后执行一条带条件的更新：只有状态是 ongoing 才改成已交卷。影响行数是 1，说明我是第一次交卷；如果影响行数是 0，说明已经交过，直接返回第一次的结果，并标记 replayed。所以重复点击、网络重试、多标签页同时交，都不会产生第二份成绩。

**可能失败与兜底话术**

- 提示"不在考试范围 / 作答次数已用尽"：回 T4 确认参考班级包含该学生、最大次数为 1 且未使用；或用教师端"补考授权"加 1 次。
- 提示"考试尚未开始 / 已结束"：回 T4 把窗口改到当前前后；教师端对已发布考试只允许改时间、说明与防作弊开关。
- 刷新后掉登录：前端会用刷新令牌自动换新访问令牌；若失败，重新登录后重新进入该答卷，仍会恢复同一份。
- 倒计时显示 00:00 且自动交卷：说明窗口已过或时长设置过短；改用种子考试或重新发布。
- 交卷 409 / 40109：通常表示已交卷；刷新成绩页确认，不要重复操作。此时正好讲"幂等"。
- 全屏被浏览器拦截：按 `Esc` 退出后重新点"进入考试"；或直接说明"全屏是体验层，不是安全边界"。

### T6 · 08:40-10:10 · 自动判分与教师人工复核（90 秒）

**目标**：展示"客观题秒判 + 简答题人工"的分工，以及评分校验、总分回写、进度刷新。

**操作路径与点击顺序**

1. 切回教师标签，左侧点击"阅卷与复核"，进入 `/teacher/reviews`。
2. 考试筛选选择刚发布的"演示考试 · 软件工程综合"，状态筛选"待阅"。
3. 队列中出现 1 条主观题任务，点击进入详情。
4. 左侧考生答案、右侧参考答案与采分点并排展示。
5. 按采分点给分：三部分 6 分、Header 作用 4 分、Signature 作用 5 分，合计 15 分；Payload 声明那项 5 分因未答到而不给（按实际作答可微调）。
6. 填写评语："要点基本完整，Payload 的过期时间说明可补充。"
7. 点击"保存评分"。
8. 观察 toast、队列待阅数、阅卷进度（已阅 1 / 完成率 100%）。

**预期界面表现**

- 阅卷队列按考试与状态过滤，显示考生、题号、满分、提交时间。
- 详情页左右分栏：考生答案与参考答案/采分点；评分区有分值输入、采分点勾选、评语。
- 保存后 toast："评分已保存：本题 15 分，答卷总分 20 分"（以现场给分为准）。

- 学生端成绩详情此时仍显示"评阅中"，因为成绩尚未发布。

**旁白（可直接照读）**

> 学生交卷时，客观题已经在同一个事务里判完了。判分器是一个纯函数：输入题型、标准答案、考生答案、满分和策略，输出自动得分和是否需要人工。纯函数的好处有两个：单元测试不需要数据库；重复调用没有副作用，所以判分可以重放。
>
> 规则我举三个：单选要求长度为一且集合相等；多选先判全对，少选在 half_score 策略下得半分，错选或全错不得分；填空按空的数量和顺序逐空归一化比较，忽略大小写、全半角和多余空白；简答直接标记需要人工，不自动给分。
>
> 现在这条是简答题任务。左边是考生答案，右边是参考答案和采分点。我给分时会校验：得分必须在 0 到满分之间，采分点之和要等于总分；保存时在同一个事务里更新逐题人工分、最终分、答卷总分和及格状态，同时写一条成绩变更日志。
>
> 所以任何一个分数变化都能解释：谁改的、什么时候、从多少到多少、依据是什么。

**可能失败与兜底话术**

- 队列为空：确认学生已交卷、考试归属该教师；若刚交卷，刷新一次或切换筛选。
- 提示"采分点合计不等于得分"：现场调整勾选使两者一致；顺势说明校验规则。
- 提示"该任务已完成"：说明重复评分被拒绝；改看进度卡与成绩变更日志。
- 评分后学生端仍显示"评阅中"：这是正确行为，成绩发布在 T7 才做。

### T7 · 10:10-11:40 · 成绩统计、图表与发布（90 秒）

**目标**：展示统计口径、分数段图、题目质量与知识点失分，以及发布控制。

**操作路径与点击顺序**

1. 教师左侧点击"成绩统计"，进入 `/teacher/stats`。
2. 选择"演示考试 · 软件工程综合"。
3. 依次指出指标卡：应考 1、实考 1、交卷率 100%、平均分、最高分、最低分、及格率、优秀率。
4. 指向 SVG 分数段柱状图，说明分数段分布。
5. 向下滚动到题目质量表：正确率、难度系数、区分度、异常标记。
6. 指向知识点失分条形图。
7. 点击"发布成绩"，确认弹窗，观察 toast"成绩已发布，通知 N 名学生"。
8. 切到学生标签，左侧点击"我的成绩"，刷新 `/student/results`，从"评阅中"变为可查看分数；点进详情展示逐题得分、标准答案、解析、评语、申诉入口。

**预期界面表现**

- 指标卡显示应考/实考/交卷率/平均分/最高/最低/及格率/优秀率，比例字段为 0~100 的百分数。
- 分数段柱状图为原生 SVG，不依赖图表库；每段有标签与人数。
- 题目质量表标出正确率低于 30% 或高于 95% 的异常题。
- 发布后学生成绩列表由"评阅中"变为分数；成绩详情展示逐题 finalScore 与教师评语。
- 重复点击发布会被拒绝（60102），提示已发布。

**旁白（可直接照读）**

> 统计不是每次查询都全表算。交卷、阅卷完成、成绩发布、重判这四个事件会触发刷新，把结果写进三张物化表；查询优先读物化表，超过 5 分钟才重算。这样统计的复杂度从"随答卷数增长"变成"随刷新次数增长"。
>
> 指标口径我明确一下：应考按考试任务数，实考按已交卷答卷数，交卷率是两者之比；平均分、最高最低按总分；及格率按 `ex_exam.pass_score` 及格线；优秀率按总分达到满分 90% 及以上计算。比例字段返回 0 到 100 的百分数，不是 0 到 1。
>
> 题目质量里，正确率是答对人数除以有效作答人数，难度系数是平均得分除以满分，区分度是前 27% 与后 27% 的平均得分率之差。正确率低于 30% 或高于 95%，或者区分度低于 0.2，会被标记为异常题，提示题目可能过难、过易或有歧义。
>
> 成绩发布是一个显式动作。发布前学生只能看到"评阅中"；发布时会校验没有未完成的阅卷任务；发布后学生在申诉期内可以发起复核。这是"成绩可解释、可追溯"的最后一段。

**可能失败与兜底话术**

- 指标全为 0：刚交卷/刚评分，物化刷新有秒级延迟；切换一次考试再切回，或等 2 秒。
- 发布提示"存在未完成任务"：回 T6 把队列清空；这是发布前的强制校验。
- 图表空白：浏览器窗口过窄导致 SVG 高度塌陷，放大窗口或按 `F11`。
- 分数段与满分口径不一致：前端按接口原样展示，不自行换算；这一点在契约缺口清单第 12 项已记录。

## 六、现场应急总则

1. **先给结论，再排障**：任何页面打不开，先说"这一步应该看到什么"，再决定是否切换录屏。
2. **30 秒规则**：单个故障排查不超过 30 秒；超过立即切录屏，不在评委面前翻日志、改配置。

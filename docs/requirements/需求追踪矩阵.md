## 1 矩阵使用说明

### 1.1 列定义

| 列名 | 含义 |
| --- | --- |
| 需求编号 | 需求规格说明书中的唯一编号，REQ-模块-序号 或 NFR-序号 |
| 需求名称 | 与需求规格说明书保持一致的简称 |
| 来源角色 | 提出或主要使用该需求的角色（管理员/教师/学生/系统） |
| 优先级 | 高 / 中 / 低，与需求规格说明书一致 |
| 对应用例 | 用例图中的用例编号（UC-xx），多条以逗号分隔 |
| 后续设计章节 | 系统设计文档中的承接章节，章节编号约定见需求规格说明书 §1.8 |
| 对应用户故事 | 用户故事编号（US-xx），故事清单见 §2 |

### 1.2 状态定义

| 状态 | 含义 |
| --- | --- |
| 已实现 | 代码与测试均已完成并通过验收 |
| 进行中 | 已分配开发任务，尚未完成验收 |
| 待开发 | 需求已基线化，尚未进入开发 |
| 延后 | 因资源约束主动延期，须在论文"总结与展望"中说明 |
| 已废弃 | 需求被替代或取消，保留编号追溯 |

> 本矩阵在需求阶段建立，初始状态统一为"待开发"；开发与测试阶段由对应负责人更新状态，矩阵状态列是项目进度与验收核对的主依据。

### 1.3 覆盖性自检规则

1. 每条 REQ 必须至少映射 1 个用例与 1 个用户故事，且必须映射到设计章节。
2. 每条 NFR 必须可被至少一种验证方式度量（验证方式见需求规格说明书 §5）。
3. 用例图中每个 Actor 关联的用例必须能在本矩阵找到承接需求，不得存在"无需求来源的用例"。
4. 每次需求变更后，同步更新需求规格说明书、用例图与本矩阵，三者编号必须完全一致。

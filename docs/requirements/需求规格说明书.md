## 1 项目背景与建设目标

### 1.1 编写目的

本文档面向本科毕业设计「在线考试系统」项目，用于完整、无歧义地定义系统的功能需求与非功能需求，作为系统架构设计、接口契约设计、前后端实现、测试用例编写与论文撰写的一致基线。文档的预期读者包括：

- 系统架构师：据此完成技术选型、分层架构、数据库与 API 契约设计；
- 前端与后端开发者：据此实现页面交互与业务接口；
- 测试人员：据此设计测试用例并判定验收是否通过；
- 指导教师与答辩评委：据此评估需求完整性、可追溯性与工程规范性。

### 1.2 项目背景

考试是教学过程中检验学习效果、反馈教学质量的核心环节。传统线下考试在命题、印卷、监考、阅卷、登分、统计等环节高度依赖人工，存在周期长、成本高、易出错、成绩分析维度单一等问题。近年来，随着高校信息化基础设施的完善与在线教学的常态化，在线考试系统已成为教务教学平台的必备组成部分。

然而，现有在线考试产品多呈现两个极端：一类是面向课堂教学互动的轻量工具，正式考试能力不足；另一类是功能庞杂的商业平台，部署成本高、流程固化、数据难以自主掌控。对于院系级、课程级的中小规模正式考试场景，亟需一套**流程闭环、判分可靠、统计可分析、部署轻量**的在线考试系统。

本项目面向高校课程考试场景，采用 React 18 + Vite、Node.js + Express、MySQL 8 的前后端分离技术栈，构建覆盖「题库管理—组卷—考试发布—在线答题—自动阅卷—人工复核—成绩统计」全流程的在线考试系统，并作为本科毕业设计验证软件工程全流程实践能力。

### 1.3 同类系统现状调研

为明确本系统的差异化定位，选取国内外 6 个具有代表性的在线考试/学习平台进行对比分析。

| 序号 | 系统名称 | 类型 | 核心考试能力 | 主要优点 | 主要不足 |
| --- | --- | --- | --- | --- | --- |
| 1 | Moodle（Quiz 模块） | 开源 LMS | 题型插件丰富、题库分类、随机抽题、自动判分、基础统计 | 开源可私有化部署；题型扩展机制成熟；题库支持分类与随机题 | 界面与交互陈旧；部署与运维门槛较高；中文统计报表与可视化能力弱；防作弊依赖插件 |
| 2 | Canvas LMS | 开源/商业 LMS | Quiz 与 New Quizzes、题库、自动判分、Outcome 对齐 | 现代化 UI；REST API 完善；学习成果对齐能力强 | 高级题型与防作弊能力有限；自建与二次开发复杂度高；正式考试流程（阅卷仲裁、复核）不完整 |

| 5 | 雨课堂 | 国内课堂互动工具 | 随堂测验、限时答题、投票、数据反馈 | 微信入口低门槛；课堂互动与即时反馈优秀 | 面向随堂轻量测验，正式考试能力弱；主观题阅卷、防作弊、成绩统计与归档能力不足 |

### 1.4 现有方案的不足与本系统切入点

综合调研结果，现有方案在以下方面存在共性不足，构成本系统的设计切入点：

1. **流程闭环不完整**：多数产品覆盖「组卷—答题—判分」，但主观题人工阅卷、双评仲裁、成绩复核申诉、成绩发布控制之间存在断点，成绩一旦出错缺少可追溯的纠正路径。
2. **组卷智能化不足**：随机组卷多停留在"按题型随机"，缺少按难度分布、知识点覆盖比例、去重与缺口提示的规则化组卷能力。
3. **判分可靠性缺乏工程保障**：交卷与判分过程缺少幂等设计、服务端计时与答案脱敏，网络异常时易出现重复判分、答案泄露或计时失真。
4. **成绩分析维度浅**：普遍只提供平均分与排名，缺少题目正确率、难度系数、区分度、知识点失分分布等教学诊断指标。
5. **防作弊能力依赖外部服务**：摄像头监考、人脸识别等能力成本高，且难以与校内流程结合；轻量场景缺少切屏、复制粘贴、多端登录等基础行为留痕。
6. **数据主权与部署成本**：SaaS 产品数据不在校内，开源平台部署运维复杂，院系级场景缺少"轻量可私有化、功能刚好够用"的方案。

本系统不追求大而全，而是聚焦**课程级正式考试**场景，以轻量技术栈实现完整闭环，并通过规则化组卷、服务端计时、幂等交卷、客观题自动判分、题目质量分析等设计补齐上述短板。

### 1.5 建设目标

| 目标编号 | 目标描述 | 可衡量标准 |
| --- | --- | --- |
| G1 | 实现考试全流程闭环 | 题库、组卷、考试、答题、阅卷、复核、统计、归档 8 个环节均有可运行功能与可追溯需求编号 |
| G2 | 保障考试过程公平可靠 | 服务端计时、答案脱敏、幂等交卷、防作弊事件留痕全部实现，异常场景可恢复 |
| G3 | 提升阅卷效率 | 客观题自动判分，主观题在线评分，支持阅卷进度监控与争议仲裁 |
| G4 | 提供教学决策数据 | 提供单场统计、题目质量分析、知识点失分分布、多场次趋势对比与导出 |
| G5 | 满足安全与合规要求 | JWT + RBAC 鉴权、密码不可逆存储、敏感操作审计、越权访问拦截 |
| G6 | 形成规范可追溯的工程交付 | 需求—用例—设计—接口—测试—论文全链路可追溯，追踪矩阵覆盖率 100% |

### 1.6 研究意义

1. **教学价值**：将教师从重复性命题、阅卷、登分劳动中释放出来，把考试数据转化为可操作的教学诊断结论。
2. **技术价值**：在轻量技术栈下系统实践前后端分离、RBAC、JWT 令牌轮换、服务端权威计时、幂等交卷、判分规则引擎、软删除与数据快照等工程方法。
3. **工程价值**：以需求追踪矩阵为主线，贯通需求、用例、设计、接口、测试与论文，形成可复用的小型软件工程实践范例。
4. **管理价值**：通过审计日志、成绩发布控制、复核申诉流程，使考试结果具备可解释性与可追溯性。

## 2 术语定义与缩略语

| 术语 / 缩略语 | 英文 | 定义 |

| 答卷 | Attempt | 某考生对某场考试的一次作答记录，是判分与成绩的载体 |

| 自动判分 | Auto Grading | 依据标准答案对客观题自动计算得分 |
| 人工阅卷 | Manual Grading | 教师对主观题逐题评分并填写评语 |
| 双评仲裁 | Double-marking Arbitration | 两名教师独立评分，分歧超过阈值时由第三方裁定最终分 |
| 成绩复核 | Score Review / Appeal | 考生对已发布成绩提出异议，由教师复核并回写结论 |
| 防作弊事件 | Anti-cheating Event | 切屏、退出全屏、复制粘贴、多设备并发登录等行为记录 |
| RBAC | Role-Based Access Control | 基于角色的访问控制，权限授予角色、角色授予用户 |
| JWT | JSON Web Token | 无状态令牌，用于接口鉴权 |
| Access Token | 访问令牌 | 短期令牌，用于访问业务接口，有效期 2 小时 |

| 软删除 | Soft Delete | 仅标记删除状态、保留数据的删除方式 |

| 及格率 | Pass Rate | 成绩达到及格线的考生占实考人数的比例 |
| 审计日志 | Audit Log | 记录敏感操作的不可篡改流水，用于安全追溯 |
| P95 | 95th Percentile | 95% 请求的响应时间不超过该值 |
| SPA | Single Page Application | 单页应用，本项目前端形态 |

### 3.3 权限控制规则

1. **鉴权链路**：所有业务接口（除登录、注册、健康检查外）必须校验 JWT 签名与有效期；校验通过后依据 RBAC 映射判定角色是否具备接口权限，越权返回 HTTP 403，未认证返回 HTTP 401。
2. **数据范围控制**：权限判定包含"功能权限"与"数据权限"两层。教师对题库、试卷、考试、答卷、成绩的访问均需附加创建者或授权关系过滤；学生仅能访问 `student_id` 等于本人 ID 的数据。
3. **状态约束**：权限矩阵中的 `△` 项必须叠加状态判定。例如"修改已发布考试"仅在考试未开始或经管理员授权时允许；已交卷学生不可再次作答，只能通过增加次数授权。
4. **最小权限原则**：前端按角色渲染菜单仅作体验优化，真正的权限校验必须在服务端执行，任何前端隐藏不构成安全边界。
5. **权限变更即时性**：角色或权限点变更后，用户下一次请求即按新权限判定（服务端每次请求读取当前角色，或通过令牌版本号使旧令牌失效）。
6. **敏感操作留痕**：权限矩阵中标注为管理类、成绩类、导出类的操作，均须写入审计日志（见 REQ-SYS-02）。

## 4 功能需求

### 4.0 编号规则与表述规范

1. **编号规则**：`REQ-<模块缩写>-<两位序号>`。模块缩写：UAM（User & Access Management）、QBM（Question Bank Management）、PPM（Paper & Paper-composition Management）、EXM（Exam & Online Answering）、MRK（Marking & Review）、STA（Statistics & Analysis）、SYS（System Management）。
2. **表述规范**：每条功能需求采用 EARS 模板表述——"**当**〈触发条件〉**时，系统应当**〈响应〉"，确保需求可测试、可验收。
3. **优先级定义**：
   - **高**：核心业务闭环或安全底线，缺失则系统不可验收；
   - **中**：显著提升效率或体验，缺失不影响主流程跑通；
   - **低**：增强型功能，可在资源紧张时降级或延后。
4. **输入/输出说明**：输入指触发需求所需的用户操作或系统事件；输出指系统响应的业务结果或可见反馈。

### 4.1 用户与权限管理（UAM）

**模块目标**：建立可信的身份认证与最小权限访问控制，支撑三角色数据隔离。

**模块规则**：账号统一以用户名（学生为学号、教师为工号）作为登录标识；密码采用 bcrypt 加盐哈希存储；权限校验在服务端执行；所有登录与权限变更行为留痕。

| 需求编号 | 需求名称 | EARS 需求描述 | 输入 | 输出 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| REQ-UAM-01 | 账号登录 | 当用户在登录页提交用户名与密码时，系统应当校验凭证有效性、账号状态与锁定状态，校验通过后签发有效期 2 小时的 Access Token 与 7 天的 Refresh Token，并按角色跳转至对应工作台 | 用户名、密码、图形验证码 | 令牌对、用户基本信息、角色与工作台路由；失败时返回统一错误提示 | 高 |
| REQ-UAM-02 | 登录失败锁定 | 当同一账号在 15 分钟内连续登录失败达到 5 次时，系统应当锁定该账号 15 分钟，向登录方返回剩余锁定时间，并写入安全审计日志 | 连续失败事件（账号、IP、时间） | 锁定状态与剩余秒数；审计日志记录 | 高 |
| REQ-UAM-03 | 令牌刷新与轮换 | 当客户端携带有效期内的 Refresh Token 请求刷新令牌时，系统应当校验令牌签名、白名单状态与用户状态，签发新的 Access Token 并同时轮换 Refresh Token，使旧 Refresh Token 立即失效 | Refresh Token | 新的令牌对与过期时间；令牌无效时返回 401 | 高 |
| REQ-UAM-04 | 安全登出 | 当已登录用户主动退出登录时，系统应当吊销当前 Refresh Token、清除服务端会话记录并写入登出事件，前端清理本地令牌并跳转登录页 | 用户登出指令、当前令牌 | 登出成功响应；会话失效 | 中 |
| REQ-UAM-05 | 用户创建 | 当管理员提交新用户信息（用户名、姓名、邮箱、角色、所属班级或部门）时，系统应当校验用户名与邮箱的唯一性，生成初始随机密码并以 bcrypt 哈希存储，返回创建结果并一次性展示初始密码 | 新用户表单数据 | 用户 ID、初始密码（仅展示一次）、创建结果 | 高 |
| REQ-UAM-06 | 学生注册与审批 | 当访客提交学生注册申请（学号、姓名、班级、邮箱、密码）时，系统应当创建状态为"待审核"的账号并通知管理员；在管理员审核通过前，该账号不得登录系统 | 注册表单 | 待审核账号记录、申请受理提示 | 中 |
| REQ-UAM-07 | 密码修改与强度校验 | 当用户提交旧密码与新密码时，系统应当校验旧密码正确性与新密码强度（长度不少于 8 位、同时包含大小写字母与数字），更新哈希值并吊销该用户全部 Refresh Token，要求重新登录 | 旧密码、新密码、确认密码 | 修改结果；强制重新登录提示 | 高 |
| REQ-UAM-08 | 角色与权限分配 | 当管理员调整用户的角色或权限点时，系统应当更新 RBAC 映射关系，使该用户下一次请求即按新权限判定，并写入操作审计日志 | 用户 ID、目标角色、权限点集合 | 更新结果；新权限即时生效 | 高 |
| REQ-UAM-09 | 账号启用与禁用 | 当管理员将账号状态置为禁用时，系统应当立即拒绝该账号的登录请求及已签发令牌的后续请求，同时完整保留其历史考试、答卷与成绩数据 | 用户 ID、目标状态、禁用原因 | 状态变更结果；审计记录 | 中 |

### 4.2 题库管理（QBM）

**模块目标**：建设可复用、可检索、可版本留痕的题库，为组卷提供高质量题目供给。

**模块规则**：题型限定为单选、多选、判断、填空、简答五类；题目归属创建者题库；被引用题目不可物理删除；修改题目不影响已开始考试的题目快照。

| 需求编号 | 需求名称 | EARS 需求描述 | 输入 | 输出 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| REQ-QBM-01 | 题目新增 | 当教师在题目编辑页提交题干、题型、选项、标准答案、解析、分值与难度时，系统应当按题型校验必填项与答案合法性（如单选题答案唯一、多选题答案集合非空、填空题答案非空），校验通过后保存并返回题目编号 | 题目表单（题型相关字段） | 题目 ID、保存结果；校验失败时返回字段级错误 | 高 |
| REQ-QBM-02 | 题目编辑与版本留痕 | 当教师修改已保存的题目时，系统应当保存修改内容并生成一条题目版本记录（修改人、修改时间、变更前后快照），保证历史考试所引用的题目内容可追溯 | 题目 ID、修改后内容 | 更新结果、版本号；版本历史可查询 | 高 |
| REQ-QBM-03 | 题目删除保护 | 当用户删除题目时，系统应当执行软删除；若该题目已被任何未归档试卷或进行中的考试引用，系统应当拒绝删除并返回引用清单（试卷名、考试名） | 题目 ID | 删除结果或拒绝原因与引用清单 | 高 |
| REQ-QBM-04 | 题目多条件检索 | 当教师或管理员输入关键词并选择题型、难度、知识点、创建人等筛选条件时，系统应当分页返回匹配题目列表，默认每页 20 条，列表查询 P95 响应时间不超过 500ms | 关键词、筛选条件、页码与每页条数 | 分页题目列表、总数 | 高 |
| REQ-QBM-05 | 题目批量导入 | 当教师上传符合模板的 Excel 或 CSV 文件时，系统应当逐行校验题型、答案与分值合法性并批量入库，返回成功条数与失败明细（行号、失败原因），单文件行数上限 5000 行 | 题库文件、目标题库与知识点 | 导入结果统计、失败明细清单 | 中 |
| REQ-QBM-06 | 题库导出 | 当教师按筛选条件触发导出时，系统应当生成包含题干、选项、标准答案、解析、难度与知识点的 Excel 文件，并记录导出操作审计 | 筛选条件、导出格式 | Excel 文件下载、审计记录 | 中 |
| REQ-QBM-07 | 知识点与难度维护 | 当管理员新增、重命名或归档知识点（支持两级分类）时，系统应当更新知识点树并同步题目筛选选项；已被题目引用的知识点禁止物理删除，仅可归档 | 知识点名称、父级、排序、状态 | 知识点树最新结构 | 中 |

### 4.3 试卷与组卷管理（PPM）

**模块目标**：支持手动与规则化随机组卷，保证试卷结构、分值与使用状态可控。

**模块规则**：试卷引用题目时保存题目快照引用；总分必须等于各题分值之和；被考试引用的试卷锁定；试卷可复制但不可跨教师越权使用。

| 需求编号 | 需求名称 | EARS 需求描述 | 输入 | 输出 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| REQ-PPM-01 | 手动组卷 | 当教师创建试卷并逐题加入题目时，系统应当实时累计题数与总分，保存题目顺序与每题分值，并校验试卷至少包含 1 道题 | 试卷基本信息、题目 ID 列表、每题分值 | 试卷结构、题数与总分 | 高 |
| REQ-PPM-02 | 随机组卷 | 当教师设定各题型数量、难度分布比例与知识点范围并触发随机组卷时，系统应当从符合规则的题目中无重复抽题生成试卷草稿；当可用题目不足时，系统应当给出各规则维度的缺口提示且不生成残缺试卷 | 题型数量、难度比例、知识点范围、可用题库 | 试卷草稿（题目列表）；或缺口明细 | 高 |
| REQ-PPM-03 | 试卷分值校验 | 当教师保存或发布试卷时，系统应当校验各题分值之和等于设定总分；不一致时拒绝保存并提示差额与逐题分值明细 | 试卷 ID、总分设定、各题分值 | 校验通过结果；或差额提示 | 高 |
| REQ-PPM-04 | 试卷预览 | 当教师点击试卷预览时，系统应当以考生视角渲染整卷（题号、题干、选项、分值与答题控件），预览页面不展示标准答案与解析 | 试卷 ID | 考生视角预览页面 | 中 |
| REQ-PPM-05 | 试卷复制 | 当教师复制已有试卷时，系统应当生成一份独立的新试卷（题目引用共享、题目顺序与分值可独立编辑），原试卷内容保持不变 | 源试卷 ID、新试卷名称 | 新试卷 ID 与结构 | 中 |
| REQ-PPM-06 | 试卷锁定与归档 | 当试卷被考试引用时，系统应当将其置为锁定状态并禁止修改题目与分值；当管理员归档长期不用的试卷时，系统应当禁止该试卷再用于创建新考试，历史考试数据不受影响 | 试卷 ID、目标状态 | 锁定或归档结果；违规操作提示 | 高 |
| REQ-PPM-07 | 试卷检索 | 当教师输入试卷名称、状态、创建时间或关联考试等条件时，系统应当分页返回试卷列表，展示题数、总分与已使用次数 | 检索条件、分页参数 | 分页试卷列表 | 中 |

### 4.4 考试与在线答题（EXM）

**模块目标**：保障考试发布、作答、计时、交卷全过程的公平性、可靠性与异常可恢复性。

**模块规则**：考试以服务端时间为唯一权威；题目下发必须脱敏；交卷必须幂等；答卷保存必须容错；考试窗口外禁止作答。

| 需求编号 | 需求名称 | EARS 需求描述 | 输入 | 输出 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| REQ-EXM-01 | 创建考试 | 当教师选择试卷并填写考试名称、开始与结束时间、答题时长、参考范围（班级或指定学生）、允许次数、及格线与防作弊开关时，系统应当创建草稿状态考试，并校验结束时间晚于开始时间、答题时长不超过考试窗口长度 | 考试配置表单 | 考试 ID、草稿状态；校验失败原因 | 高 |
| REQ-EXM-02 | 发布考试与学生可见 | 当教师发布考试时，系统应当将状态置为"已发布"，为参考学生生成考试任务并推送站内通知，使学生端出现可参加考试入口 | 考试 ID、参考范围 | 发布结果、考试任务、通知记录 | 高 |
| REQ-EXM-03 | 考生资格校验 | 当学生进入考试入口时，系统应当校验其是否在参考名单内、当前时间是否处于考试窗口、剩余作答次数是否大于 0，任一条件不满足时返回具体原因并拒绝下发试题 | 学生 ID、考试 ID、服务端当前时间 | 校验通过凭证；或拒绝原因 | 高 |
| REQ-EXM-04 | 开考与答卷下发 | 当资格校验通过且学生确认开考时，系统应当创建唯一答卷记录，以服务端时间计算截止时间，下发不含标准答案与解析的题目快照，并按配置对学生维度打乱题目顺序 | 学生 ID、考试 ID、开考确认 | 答卷 ID、题目快照、截止时间 | 高 |
| REQ-EXM-05 | 答案自动暂存 | 当学生在答题过程中切换题目、修改答案或答题间隔达到 30 秒时，系统应当将当前答案增量保存至服务端草稿，保存动作不影响考试计时 | 答卷 ID、题目 ID、作答内容 | 暂存成功标记与暂存时间 | 高 |
| REQ-EXM-06 | 服务端权威计时 | 当学生处于考试进行中时，系统应当以服务端时间为基准向前端下发剩余秒数并每 30 秒校准一次，客户端本地倒计时仅用于展示，不作为交卷判定依据 | 答卷 ID、服务端当前时间 | 剩余秒数、校准时间戳 | 高 |
| REQ-EXM-07 | 交卷 | 当学生点击交卷或剩余时间归零时，系统应当执行幂等交卷：固化答卷快照、禁止继续作答、写入交卷时间与状态，并触发自动判分流程；重复交卷请求返回同一结果 | 答卷 ID、交卷触发方式（手动或超时） | 交卷结果、答卷最终状态、判分任务标识 | 高 |
| REQ-EXM-08 | 断线重连恢复 | 当学生在考试中断网、刷新页面或更换浏览器重新进入时，系统应当校验答卷状态，恢复剩余时间与已保存答案，不重复计时且不丢失已暂存内容 | 学生 ID、考试 ID、已存在答卷 | 恢复后的试卷视图、剩余时间、已保存答案 | 高 |
| REQ-EXM-09 | 防作弊事件采集 | 当防作弊开关开启且检测到切屏、退出全屏、复制粘贴或同一账号多设备并发登录时，系统应当记录事件类型、发生时间与累计次数；超过配置阈值时标记答卷为异常并通知监考教师 | 浏览器事件、登录会话、阈值配置 | 防作弊事件记录、答卷异常标记、通知 | 高 |
| REQ-EXM-10 | 考试变更与补考授权 | 当教师或管理员对已发布考试执行延期、取消或为指定学生增加作答次数时，系统应当校验变更合法性（如考试未归档、学生未超过次数上限），更新考试或授权记录并向受影响学生推送通知 | 考试 ID、变更类型、目标学生 | 变更结果、通知记录；非法变更拒绝原因 | 中 |

### 4.5 自动阅卷与人工复核（MRK）

**模块目标**：在保证判分准确的前提下压缩阅卷周期，并为成绩争议提供可追溯的纠正路径。

**模块规则**：客观题判分规则由系统参数配置（多选支持"全对得分"或"少选得半分"）；主观题必须人工评分；成绩变更必须留痕（原值、新值、操作人、原因）。

| 需求编号 | 需求名称 | EARS 需求描述 | 输入 | 输出 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| REQ-MRK-01 | 客观题自动判分 | 当答卷完成交卷时，系统应当依据题目快照中的标准答案对单选、多选、判断、填空题自动判分（多选按配置的全对得分或少选得半分规则），并在 10 秒内写入逐题得分与客观题小计 | 已交卷答卷、题目快照、计分策略 | 逐题得分、客观题小计、判分完成状态 | 高 |
| REQ-MRK-02 | 主观题阅卷队列 | 当答卷包含简答或论述类主观题时，系统应当将答卷加入人工阅卷队列，按题分配阅卷任务并展示待阅数量与队列顺序 | 已交卷答卷、主观题清单 | 阅卷任务、待阅计数 | 高 |
| REQ-MRK-03 | 人工评分 | 当教师打开待阅答卷时，系统应当并排展示考生答案与参考答案，允许按采分点给分并填写评语，校验得分处于 0 至该题满分的区间后保存，并实时更新答卷总分 | 答卷 ID、题目 ID、得分、评语 | 评分保存结果、更新的答卷总分 | 高 |
| REQ-MRK-04 | 双评与争议仲裁 | 当阅卷配置为双评且两名教师对同一题的打分差值超过满分 20% 时，系统应当将该题转入仲裁队列，由管理员或被指定的教研组长裁定最终得分，并在成绩中记录三方评分 | 双评得分、仲裁阈值、仲裁人裁定分 | 仲裁任务、最终得分、评分痕迹 | 中 |
| REQ-MRK-05 | 成绩复核申诉 | 当学生在申诉期内对已发布成绩提交复核申请（选择题目并填写理由）时，系统应当生成复核工单并通知任课教师；复核结论回写成绩时保留修改前后值、复核人与复核理由 | 学生 ID、考试 ID、题目 ID、申诉理由 | 复核工单、处理状态、成绩变更记录 | 中 |
| REQ-MRK-06 | 阅卷进度监控 | 当教师或管理员进入阅卷看板时，系统应当实时展示总答卷数、已阅数、待阅数、阅卷完成率与按阅卷人维度的工作量，并支持筛选待阅答卷 | 考试 ID、阅卷人筛选条件 | 进度看板数据、待阅列表 | 中 |
| REQ-MRK-07 | 标准答案修正与批量重判 | 当管理员修正某题标准答案并触发重判时，系统应当仅对引用该题的答卷重新计算该题客观分与总分，保持主观题人工得分不变，并生成包含原分与新分的重判审计记录 | 题目 ID、新标准答案、重判范围 | 重判结果统计、成绩变更明细、审计记录 | 中 |

### 4.6 成绩统计与分析（STA）

**模块目标**：将考试结果转化为教师可用的教学诊断数据，并向学生提供透明、可解释的成绩反馈。

**模块规则**：成绩数据仅对具备数据权限的角色开放；成绩发布前学生不可见具体分数；统计口径须在页面明示（如实考人数、缺考人数）。

| 需求编号 | 需求名称 | EARS 需求描述 | 输入 | 输出 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| REQ-STA-01 | 个人成绩查询 | 当学生在成绩页选择某场已发布成绩的考试时，系统应当展示总分、客观题与主观题分项得分、及格状态、班级排名区间与逐题得分，主观题同时展示教师评语 | 学生 ID、考试 ID | 成绩详情、逐题得分、评语 | 高 |
| REQ-STA-02 | 单场考试统计 | 当教师查看某场考试统计时，系统应当计算参考人数、缺考人数、交卷率、平均分、最高分、最低分、标准差、及格率与分数段分布，数据随交卷与阅卷实时刷新 | 考试 ID、统计维度 | 单场统计指标、分数段分布 | 高 |
| REQ-STA-03 | 题目质量分析 | 当教师查看题目分析时，系统应当按题输出正确率、平均得分率、难度系数与区分度（前后 27% 分组法），并标记异常题（正确率低于 30% 或高于 95%） | 考试 ID、题目维度 | 逐题质量指标、异常题标记 | 中 |
| REQ-STA-04 | 趋势与对比分析 | 当教师选择多场考试或多个班级时，系统应当生成平均分、及格率、优秀率的时间序列对比，并支持按知识点维度聚合失分分布 | 考试 ID 集合、班级集合、知识点维度 | 对比图表数据、知识点失分分布 | 中 |
| REQ-STA-05 | 成绩发布控制 | 当教师确认发布成绩时，系统应当校验阅卷完成情况，将成绩状态置为"已发布"并对参考学生可见；未发布前学生仅能看到"评阅中"状态 | 考试 ID、发布确认 | 发布结果、学生可见状态 | 高 |
| REQ-STA-06 | 成绩导出 | 当教师或管理员触发成绩导出时，系统应当生成包含学号、姓名、总分、分项得分与排名的 Excel 文件，并将导出行为写入审计日志 | 考试 ID、导出范围 | Excel 文件、审计记录 | 中 |
| REQ-STA-07 | 统计图表渲染 | 当用户打开统计页面时，系统应当以柱状图、折线图与饼图渲染分布与趋势数据，并在 1280×720 及以上分辨率自适应显示 | 统计数据接口返回 | 可视化图表 | 低 |

### 4.7 系统管理（SYS）

**模块目标**：提供参数可配置、行为可审计、数据可备份、状态可观测的运行支撑能力。

**模块规则**：系统参数变更与敏感操作必须留痕；审计日志只读；备份策略需在部署文档中说明。

| 需求编号 | 需求名称 | EARS 需求描述 | 输入 | 输出 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| REQ-SYS-01 | 系统参数配置 | 当管理员修改系统参数（默认考试时长、及格线、自动暂存间隔、防作弊阈值、令牌有效期、多选计分策略）时，系统应当校验取值范围、持久化配置并使变更即时生效，同时写入审计日志 | 参数键、参数值 | 保存结果、生效确认、审计记录 | 中 |
| REQ-SYS-02 | 操作审计日志 | 当发生登录、登出、数据新增修改删除、权限变更、标准答案修正、成绩发布与成绩导出等敏感操作时，系统应当记录操作人、角色、IP、接口、请求摘要、执行结果与时间戳，且日志不可被非管理员修改或删除 | 敏感操作事件 | 审计日志记录 | 高 |
| REQ-SYS-03 | 审计日志检索与导出 | 当管理员按时间范围、操作人、操作类型检索审计日志时，系统应当分页返回结果并支持导出，默认查询范围为最近 30 天 | 检索条件、分页参数、导出指令 | 日志列表、导出文件 | 中 |
| REQ-SYS-04 | 公告管理 | 当管理员发布、编辑或下线系统公告时，系统应当按目标角色推送至对应工作台首页，并记录公告有效期与状态 | 公告标题、正文、目标角色、有效期 | 公告记录、工作台展示 | 低 |
| REQ-SYS-05 | 数据备份与恢复 | 当到达每日备份时间点或管理员手动触发备份时，系统应当执行 MySQL 逻辑备份并保留最近 7 份，同时提供服务恢复操作指引与备份记录查询 | 备份触发方式、备份策略 | 备份文件记录、执行结果 | 中 |
| REQ-SYS-06 | 系统健康检查 | 当运维系统或管理员访问健康检查接口时，系统应当返回服务运行状态、数据库连通性、版本号与服务器当前时间，响应时间不超过 200ms | 健康检查请求 | 结构化状态响应 | 低 |

## 7 约束与假设

### 7.1 技术约束

| 编号 | 约束内容 |
| --- | --- |
| C-01 | 前端固定采用 React 18 + Vite 构建，使用 SPA 路由，不引入服务端渲染 |
| C-02 | 后端固定采用 Node.js（18 LTS 及以上）+ Express 4，RESTful 风格接口，统一前缀 `/api/v1` |
| C-03 | 数据库固定采用 MySQL 8.0，字符集 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci` |
| C-04 | 鉴权采用 JWT（HS256）+ RBAC，不引入 OAuth2 或 CAS 单点登录 |
| C-05 | 不引入消息队列与微服务，异步判分通过进程内任务或定时轮询实现 |
| C-06 | 不依赖第三方 SaaS 能力（人脸识别、短信、云监考），防作弊仅实现浏览器侧行为采集 |
| C-07 | 不提供原生移动端 App，仅提供响应式 Web 页面 |

### 7.2 部署与运行约束

| 编号 | 约束内容 |
| --- | --- |
| C-08 | MySQL 8.0 单实例部署，数据库与应用服务可同机或分机部署，通过环境变量配置连接 |
| C-09 | 生产环境由 Nginx 反向代理并提供 HTTPS，Node 服务以非 root 用户运行 |
| C-10 | 数据库以 UTC 存储时间，应用层统一按 `Asia/Shanghai` 展示；服务端时间为考试计时唯一基准 |
| C-11 | 单场考试参考人数上限按 500 人设计，系统总用户规模按 5000 人设计 |
| C-12 | 单表数据量按答卷 100 万行、答题明细 500 万行设计，暂不引入分库分表 |
| C-13 | 备份采用 `mysqldump` 逻辑备份，保留最近 7 份，备份文件存放于服务器独立目录 |

### 7.3 数据约束

| 编号 | 约束内容 |
| --- | --- |
| C-14 | 用户名（学号/工号）全局唯一；同一考生同一考试仅允许存在一条有效答卷记录 |

### 7.4 假设

| A-05 | 不要求实时视频监考，防作弊以行为事件采集与异常标记为主 |
| A-06 | 成绩复核在成绩发布后 7 天内可发起，具体时限可由系统参数配置 |
| A-07 | 系统面向单院校使用，暂不考虑多租户隔离与跨校数据共享 |

### 7.5 外部依赖

| 依赖项 | 用途 | 风险与应对 |
| --- | --- | --- |
| MySQL 8.0 | 业务数据持久化 | 单点风险，通过每日备份与恢复演练缓解 |
| Nginx | 反向代理、HTTPS、静态资源 | 配置错误导致不可用，纳入部署检查清单 |
| npm 公共仓库 | 依赖安装 | 锁定依赖版本并提交 lock 文件，必要时使用内网镜像 |
| 浏览器 Notification / 站内通知 | 考试与成绩通知 | 站内通知为主，不依赖浏览器推送权限 |

## 8 验收标准概要

### 8.1 功能验收

| 验收项 | 判定标准 |
| --- | --- |
| 需求覆盖 | 53 条功能需求均有对应页面与接口，需求追踪矩阵覆盖率 100% |
| 优先级通过率 | 高优先级需求 100% 通过；中优先级不低于 95%；低优先级不低于 80% |
| 角色闭环 | 管理员、教师、学生三角色均可独立完成其权限矩阵内全部允许操作，禁止操作均被拦截 |
| 全流程贯通 | 可完整演示"建题—组卷—发考—答题—交卷—判分—阅卷—发布—查分—申诉—复核—导出"一条链路 |
| 异常场景 | 超时自动交卷、断网恢复、重复交卷、越权访问、题目删除保护、试卷锁定 6 类异常均有正确响应 |

### 8.2 性能验收

| 验收项 | 判定标准 |
| --- | --- |
| 并发答题 | 200 并发提交，P95 ≤ 2s，P99 ≤ 4s，错误率 ≤ 0.1% |
| 自动判分 | 1000 份答卷 10s 内完成客观题判分 |
| 统计查询 | 10 万答卷规模下统计查询 ≤ 3s |
| 列表接口 | 分页列表 P95 ≤ 500ms |
| 首屏加载 | 局域网 LCP ≤ 2.5s |

### 8.3 安全验收

| 验收项 | 判定标准 |
| --- | --- |
| 认证 | 未携带或伪造令牌访问业务接口返回 401 |
| 越权 | 学生访问管理接口、教师访问他人考试答卷返回 403，测试用例覆盖 100% 资源类型 |
| 密码 | 数据库无明文密码，接口响应与日志无密码字段 |
| 答案保护 | 考试进行中接口响应不含标准答案与解析字段 |
| 审计 | 登录、权限变更、成绩发布、成绩导出、标准答案修正均可检索到审计记录 |
| 输入安全 | SQL 注入与 XSS 测试用例全部被拦截或转义 |

### 8.4 可靠性与可用性验收

| 验收项 | 判定标准 |
| --- | --- |
| 连续运行 | 72 小时连续运行无崩溃、无内存持续增长异常 |
| 断线恢复 | 20 次断网、刷新、服务重启场景下答案恢复成功率 100% |
| 幂等 | 同一答卷并发交卷 10 次，仅产生 1 条最终成绩且结果一致 |
| 备份恢复 | 完成 1 次备份与恢复演练，数据完整性与一致性校验通过 |

### 8.5 文档与可追溯性验收

| 验收项 | 判定标准 |
| --- | --- |
| 文档齐备 | 需求规格说明书、用例图、需求追踪矩阵、系统设计文档、API 契约、测试报告、论文齐备且版本一致 |
| 可追溯 | 每条 REQ/NFR 均可追溯至用例、设计章节、接口与测试用例 |
| 规范性 | 需求编号连续唯一；PlantUML 用例图语法正确可渲染；全中文撰写，术语一致 |

### 8.6 验收方式

1. **功能演示**：按角色分别演示权限矩阵允许与禁止的操作路径。
2. **自动化测试**：执行 Jest 单元测试与 Supertest 集成测试，核对覆盖率与通过率。
3. **性能压测**：执行 k6/autocannon 脚本，输出压测报告并归档。
4. **安全测试**：执行越权、注入、XSS、答案泄露检查脚本。
5. **文档评审**：由指导教师按第 8.5 节清单逐项核对。
